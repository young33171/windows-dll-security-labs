# 05 · 오류 기록과 원인 분석

## 1. DLL 검색 결과 없음
**증상**: Process Explorer에서 `myhack2.dll` 또는 `myhack.dll`이 검색되지 않는 시점이 있었습니다.

**해석**: 빌드가 완료돼도 DLL이 대상 프로세스에 로딩됐다는 뜻은 아닙니다. 프로세스 상태, 실행 파일 아키텍처, 경로, 정책 등에 따라 결과가 달라질 수 있습니다.

**결과**: 재부팅 뒤 `myhack2.dll` 검색에서 1건을 확인했습니다. 이 결과는 `myhack.dll`의 원격 인젝션 성공 증거와는 별개입니다.

## 2. LoadLibrary 성공 후 스택 손상
**증상**:
```text
DLL Load Success!
Run-Time Check Failure #2
Stack around the variable 'szPath' was corrupted.
```

**추정 원인**: 경로 문자열을 다루는 버퍼/포인터 연산 문제. 실제 코드의 경계 조건을 다시 점검할 필요가 있습니다.

**개선 포인트**: 버퍼 크기, 문자열 종료, 복사 길이, 포인터 산술 확인. DLL 라이프사이클 코드와 기능 코드를 분리해 테스트합니다.

## 3. 확인 범위 과대 해석 방지
**증상**: `myhack2.dll` 검색 결과 한 건을 가지고 '모든 프로세스' 로딩 성공으로 해석할 위험.

**개선**: 프로세스별 실제 모듈 목록과 검사 범위를 별도로 기록합니다. 특정 프로세스 로딩 확인과 전체 대상 로딩은 다른 결과입니다.

## 4. 공개 자료의 안전한 구성
- 격리 VM에서 수행한 학습 사실만 작성
- 실행 파일 또는 은닉 페이로드는 공개 저장소에 올리지 않음
- 스크린샷 원본을 합성하지 않음
- 확인되지 않은 성공 장면을 만들지 않음
